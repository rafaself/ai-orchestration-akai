# Adapt the workflow to a project

Before using the workflow or copying its role profiles:

- Read the project’s `AGENTS.md`, architecture guidance, security and data-handling rules, and current development workflow.
- Decide when planning and independent review are useful. Keep the process lightweight for small, low-risk changes.
- Identify decisions that require human approval, including policy exceptions and high-risk changes.
- Follow the project’s rules for writable scope, dependencies, validation, generated files, and external tools.
- Identify who owns commits, merges, pushes, deployment, and other integration actions. The example profiles grant no independent authority for these actions.
- Adjust profile sandbox settings and instructions to match the target environment.

The workflow does not enforce approvals or phase transitions. Project instructions and authorized owners remain the source of truth.
